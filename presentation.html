Contexte

sensor.community, c'est quoi ?

Projet citoyen mondial

Des milliers de personnes dans le monde construisent leurs propres capteurs pour mesurer la qualité de l'air (PM2.5, température, pression) et publient leurs données sur une carte mondiale open data.

Données publiques & collaboratives

Chaque capteur enregistré envoie ses mesures à l'API sensor.community, qui les affiche en temps réel sur une carte accessible à tous.

Le problème

Pourquoi le WiFi ne suffit pas

Couverture limitée

En forêt, en zone rurale, sur un toit ou en plein champ : pas de WiFi. Les zones les plus intéressantes à mesurer sont précisément celles sans réseau.

Consommation élevée

Le module WiFi d'un ESP32 consomme ~160 mA en transmission. Sur batterie, cela donne une autonomie de quelques heures seulement.

Portée insuffisante

La portée WiFi est de ~50 m en extérieur. Pour couvrir un quartier, un parc ou une forêt, il faudrait des dizaines de routeurs.

Un capteur environnemental qui dépend d'une infrastructure WiFi fixe n'est pas vraiment autonome.

Nos paramètres LoRa

868 MHz SF7 BW 125 kHz CR 4/5

Principe

LoRa n'est pas LoRaWAN, pas de réseau opérateur. Nous utilisons la radio LoRa en point à point entre la carte capteur et la gateway, sans abonnement, sans TTN.

Puces utilisées

SX1276 sur le T-Beam (émetteur)
SX1262 sur le Heltec (récepteur)

Backend

API & Forward sensor.community

Endpoint principal

POST /api/v1/measurements Authorization: Bearer <token> → 201 Created (succès) → 409 Conflict (mesure déjà reçue)

Payload accepté

Le backend reçoit les mesures de la gateway, les stocke, puis les transmet automatiquement vers sensor.community.

Worker sensor_community.py

  • PIN 1 : Poussière (GP2Y)
  • PIN 11 : BME280 (temp, pression)
  • Envoi asynchrone vers sensor.community

Flux complet

  • Gateway reçoit LoRa → HTTP POST vers backend
  • Backend stocke la mesure (201 Created)
  • Worker publie sur sensor.community (PIN 1 + 11)
  • Données visibles sur la carte mondiale
